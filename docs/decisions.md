# 设计决策

| 问题 | 当前采用 | 原因与边界 |
| --- | --- | --- |
| 平台 | ROS 2 Humble、Ubuntu 22.04、Python ≥3.10 | 与现有控制器一致 |
| 项目边界 | 工具库和独立 ROS 工具包 | 工位应用负责业务和协同，型号仓库负责驱动与运动执行 |
| 控制接口 | 现有 API / ROS v1 标准消息 | Nero/Piper 可直接复用；新控制器遵循同一契约 |
| 遥操命令 | TCP TwistStamped | 不在工具库里管理机器人 IK 或累计位姿原点 |
| 输入 | 上游六轴 Joy，默认忽略按钮 | 保留上游接口，按摇帽偏转连续控制速度 |
| 满量程速度 | 0.02 m/s、0.1 rad/s，向量限幅 | 可配置；默认值是输入转换比例，非实测速度保证 |
| 操作模式 | 默认无需按钮，启动/断流后先回中 | 可用 require_deadman=true 恢复按住按钮模式 |
| 空闲输出 | 三个零速度样本后停止发布 | 避免持续接管工位规划 |
| 超时 | 工具 0.15 s，控制器独立约 0.2 s | 分别覆盖源断流和工具进程退出 |
| 使能 | 由操作者或工位显式执行 | 工具启动不使能电机 |
| 多机器人 | 每实例一个 namespace | 控制权和协同由工位应用负责 |
| Python 客户端 | 标准库 HTTP，ROS 可选 | 无厂商依赖；高频流推荐 ROS 或控制器 WebSocket |
| 子模块 | 固定已公开的 commit | 上游改动先创建分支，经验收和 PR 合并 |
| 系统驱动 | spacenavd 1.3.1 由 systemd 管理 | 后台运行、开机启动，不依赖前台终端 |
| 验证 | 自动化仿真和现场验收分别记录 | 流程通过不等于运动质量或安全等级通过 |

待扩展事项：物理轴方向标定和 USB 拔插验收、Piper namespace CLI、跨 ROS/HTTP/WebSocket
的控制租约、控制器命令时间戳检查、状态录制回放、夹爪能力以及 UR/Duco 控制器。
现场已观察到的跟踪峰值见 [Piper 验证记录](spacemouse-piper-validation.md)。
